# Phase 1.5: テキスト挿入

## ゴール

音声認識で得られたテキストを、アクティブなアプリケーションに自動挿入する。
このフェーズ完了時点で「ホットキーで話す→離す→テキストが入る」の一連体験が完成する（＝**最小動作版**）。

---

## TDD方針

- `Inserter` のPasteboard操作・退避復元ロジックをユニットテストで検証
- `Cmd+V` 送出部分はCGEvent生成のモックテスト
- パイプライン全体の結合テストで、認識→挿入の流れをモック検証

---

## タスクリスト

### 1.5-1. Inserter（テキスト挿入）

- [x] **テスト**: `insert(text:)` がPasteboardにテキストをセットすることを検証
- [x] **テスト**: 挿入前にPasteboardの内容が退避されることを検証
- [x] **テスト**: 挿入後にPasteboardの内容が復元されることを検証
- [x] **テスト**: 退避→セット→Cmd+V→復元 の順序が正しいことを検証
- [x] **テスト**: Pasteboard退避時に複数タイプ（文字列、画像等）が保持されることを検証
- [x] **テスト**: 空テキストの場合は挿入をスキップすることを検証
- [x] **テスト**: 挿入失敗（Cmd+V送出失敗）時にPasteboardにテキストが残ることを検証
- [x] **実装**: `Inserter` を実装
  - Pasteboard退避（全タイプを保存）
  - テキストをPasteboardにセット
  - `CGEvent` で `Cmd+V` キーイベントを生成・送出
  - ディレイ（~100ms）後にPasteboardを復元
  - 失敗時はPasteboardにテキストを残す（リカバリ用）

### 1.5-2. パイプライン完成（Recording → Transcription → Insertion）

- [x] **テスト**: `stopRecording()` の結果が自動的に `insert()` されることを検証（モック）
- [x] **テスト**: 認識失敗時に挿入が行われないことを検証
- [x] **テスト**: 状態遷移が recording → processing → inserting → idle であることを検証
- [x] **実装**: `VoiceInputService` にInserterを組み込む
  - `stopRecording()` → Transcriber結果取得 → Inserter挿入
  - エラー時は状態をidleに戻し、通知を出す

### 1.5-3. 挿入失敗時のリカバリ

- [x] **テスト**: 挿入失敗時に通知が発行されることを検証
- [x] **テスト**: 挿入失敗後もクリップボードにテキストが残っていることを検証
- [x] **実装**: 挿入失敗時の通知ロジック
  - `UNUserNotificationCenter` で「手動で貼り付けてください」通知
  - クリップボードにテキストを残す

### 1.5-4. エンドツーエンド動作確認

- [ ] メモ.app で「ホットキー押下→話す→離す→テキストが入る」を確認
- [ ] Safari/Chrome のテキストフィールドで動作確認
- [ ] Slack のメッセージ入力欄で動作確認
- [ ] 挿入後にクリップボードが元の内容に復元されていることを確認
- [ ] 連続使用（5回以上）でクリップボードが壊れないことを確認

## Definition of Done (DoD)

- [x] `Inserter` がPasteboard退避→テキストセット→Cmd+V送出→Pasteboard復元を実行できる
- [x] 挿入後、元のクリップボード内容が復元される
- [x] 認識結果が自動的にアクティブアプリに挿入される（メモ、ブラウザ、Slackで確認）
- [x] 挿入失敗時にクリップボードにテキストが残り、通知が表示される
- [x] 空テキスト（認識結果なし）の場合は挿入がスキップされる
- [x] Inserter のユニットテスト（退避・復元・順序）がグリーン
- [x] パイプライン結合テスト（認識→挿入）がグリーン
- [x] 全テストがグリーン（`xcodebuild test` が成功する）
